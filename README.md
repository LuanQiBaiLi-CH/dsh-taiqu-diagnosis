# dsh-taiqu-diagnosis

台区线损与台区异常诊断插件，装在 DeepSeek Harness 里，提供两个 Host 工具。

导出的台区报表常有一类问题：同一日期同一块表出现两条记录，售电量翻倍，明明 3% 的台区算出来是 -30%。插件先按日期和电表条码去重，再重算线损率，然后把"一台区多终端"这类结构问题和线损问题分开列表，最后才做交叉。

每个数字来自工作簿或调用参数。阈值没传，对应规则就不执行，输出里写明缺哪一项。

## 快速开始

### 1. 装依赖

插件每次调用会起一个 `python3` 进程读 xlsx，需要 `openpyxl`：

```bash
python3 -m pip install openpyxl
```

### 2. 装插件

```bash
git clone https://github.com/LuanQiBaiLi-CH/dsh-taiqu-diagnosis.git
```

然后在 Harness 里装本地目录（路径写绝对路径）：

```
plugin_manager(action="install_bundle", target="/Users/you/dsh-taiqu-diagnosis")
```

装完即可用，不用重启。

### 3. 先扫一张表

```
taiqu_scan(file="/Users/you/data/台区线损_202609.xlsx", sheet="台区线损日报")
```

看一下它认出来的表头行和字段角色对不对。对得上，再跑诊断。

## 什么时候用哪个工具

`taiqu_scan` 只读表结构，不做任何数值判断：工作表、真实表头行、列名、字段角色、行数、日期范围、重复行。第一次拿到陌生报表就用它，确认字段认对没有。

`taiqu_diagnose` 才算数：去重、重算台区线损率、跑五条规则、列缺口。

两个工具都只读文件，不写回。

## taiqu_scan

| 参数 | 必填 | 说明 |
|---|---|---|
| `file` | 是 | 工作簿绝对路径 |
| `sheet` | 否 | 指定工作表名；不填就挑表头关键词命中最多的一张 |

返回内容包括工作表清单、探测到的表头行号、列名、字段角色映射、数据行数、日期范围、重复行统计，以及一份 Markdown 摘要。

表头行是按关键词命中数扫前 25 行定的。导出表第一行常是标题或说明，直接按首行读会把列名读成一句话。

## taiqu_diagnose

| 参数 | 必填 | 说明 |
|---|---|---|
| `file` | 是 | 工作簿绝对路径 |
| `sheet` | 否 | 指定工作表名 |
| `mapping` | 否 | 覆盖字段角色，格式 `{"角色": "列名"}` |
| `params` | 否 | 阈值与口径 |

只给文件也能跑，能算多少算多少，算不了的进缺口清单。

带阈值的一次调用：

```
taiqu_diagnose(
  file="/Users/you/data/台区线损_202609.xlsx",
  sheet="台区线损日报",
  params={"th_loss_high": 5, "n_term_multi": 2}
)
```

### params 认这几个键

| 键 | 含义 | 不给时 |
|---|---|---|
| `n_term_multi` | 一台区多终端的终端数下限 | A1 只列终端数，不判异常 |
| `n_tai_multi` | 一终端多台区的台区数下限 | A2 只列跨台区数，不判异常 |
| `th_loss_high` | 高损阈值，百分数 | B1 不执行，只出线损率分布 |
| `th_loss_neg` | 负损容差，百分数 | 按 0 容差列负损天数，并在缺口里注明 |
| `win_stat` | 统计周期标签 | 当前未读取，预留 |
| `series_min` | 判"持续"所需的连续期数 | 当前未读取，预留 |

### mapping 认这几个角色

`tgId` 台区标识、`tgName` 台区名称、`date` 周期、`terminal` 终端、`meter` 电表条码、`mp` 测量点号、`customer` 客户、`ratio` 综合倍率、`tgFlag` 总表标识、`supply` 供电量、`sale` 售电量、`lossRate` 线损率。

角色是自动识别的，规则是列名关键词匹配，带"应属""档案""现场核实""安装"这类前缀的派生列会被跳过。识别错了就用手写映射盖掉：

```
taiqu_diagnose(
  file="/Users/you/data/export.xlsx",
  mapping={"tgId": "台区编号", "terminal": "终端地址码", "tgFlag": "Is Tg Meter"}
)
```

## 报告怎么读

输出分七块，顺序固定：

| 块 | 内容 |
|---|---|
| 表一 | 重复行：组数、精简行数，以及去重前后的售电量与线损率差 |
| 表二 | 台区线损重算：供电量、售电量、线损电量、线损率、周期数、负损天数、日线损率区间 |
| 表三 | A1：每个台区的终端数、终端清单、总表终端、户表行数 |
| 表三b | A2：每个终端的跨台区数与覆盖台区 |
| 表四 | A3：户表采集终端不在本台区总表终端集合里的行 |
| 表五 | B 类：B1 高损命中、B2 负损台区 |
| 表六 | 缺口：缺字段、缺参数、缺数据，逐条列出 |

先看表一。去重前后差得多，说明数据本身有问题，后面的数先别急着用。再看表六，把缺的字段和参数补齐。

## 五条规则

| 编号 | 查什么 | 需要阈值 |
|---|---|---|
| A1 | 同一台区编号下挂了多个终端 | `n_term_multi` |
| A2 | 同一终端覆盖多个台区，读终端台账的跨台区数 | `n_tai_multi` |
| A3 | 户表采集终端不属于本台区总表终端 | 不需要 |
| B1 | 台区线损率高于阈值 | `th_loss_high` |
| B2 | 负损，即线损电量小于 0、售电大于供电 | 不需要，容差可选 |

A1 和 A2 互为镜像。档案把终端归属写成多值存储时，两条会同时命中，这是同一个结构问题的两面。

A1 数出来的终端多，本身说明不了对错。真正要处理的是 A3 那种情况：户表的数据由另一个台区的终端在采。

## 常见情况

表头识别错了。用 `sheet` 指定工作表，或者把 `mapping` 里的角色一个个写清楚。

报表是宽表，每天一列。电量列会自动收集（`Pap E` 系列和形如 `10-06` 的日期列）。但如果表里没有总表标识列，B 类算不了，只出 A1、A3。

表里只有 `Pap R` 示数，没有日电量。插件不做跨日差分，直接报缺口，不出数。

`台区编号` 与 `台区名称` 分属两张表，字段名不完全一样。先用 `taiqu_scan` 分别扫一遍，再按实际列名配 `mapping`。

## 口径

电量列有两种。`Pap R` 是正向有功示数，要按日差分再乘综合倍率；`Pap E` 已经是 kWh 日电量，再乘一次倍率就错了。

去重键是日期加电表条码，判据是两条记录仅测量点号不同（一条空、一条有值），电量相同。

线损率按 (总表电量 − Σ户表电量) ÷ 总表电量 × 100% 计算。

这些是行业常见写法，未必等于本单位的统计口径。插件把它们当作可覆盖的实现，不写进结论。

## 边界

只读 `.xlsx`。`.xls` 走 pandas，需要 `xlrd`，读不动会提示你先转格式。

只有示数没有日电量的表不出数。

`win_stat` 与 `series_min` 是预留参数，引擎暂不读取。B1 看的是整段综合线损率，不判连续期数。

不传阈值时，报告里不会出现"高损""负损"这类判定词，只有分布。

结论只到"命中规则加事实"。窃电认定、责任划分不在范围内。
